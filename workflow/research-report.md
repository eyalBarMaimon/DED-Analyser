# Workflow: Research to Report

**Purpose:** A repeatable process for turning a topic into a clean, sourced report.  
**Output location:** Always save to `outputs/` using filename format `YYYY-MM-DD-<slug>.md`.

---

## Step 1 — Clarify Before Searching

Do NOT begin research yet. Ask the user these questions in a single message:

1. **Scope** — Broad overview or deep dive on one subtopic?
2. **Audience** — Who specifically? (e.g., solo creators, non-technical users, teams)
3. **Angle** — Specific question or perspective? (e.g., "best tools 2025", "how to get started", "X vs Y")
4. **Length** — Short brief (~300 words) or full report (~800–1000 words)?
5. **Recency** — Must be current (last 6–12 months), or is evergreen content OK?

Wait for answers before proceeding to Step 2.

---

## Step 2 — Research

- Minimum **5 sources**, aim for **7–8** for full reports
- Prefer: official docs, established tech/productivity publications (Wired, The Verge, HBR), reputable practitioner blogs
- Avoid: undated/authorless pages, SEO-farm listicles, sources older than 3 years (unless foundational)
- As you go: log every URL + one-sentence key finding; flag any contradictions between sources

---

## Step 3 — Organize Findings

Group notes into these categories before writing:

- **What it is** — definition/context
- **Why it matters** — relevance to the audience
- **How it works** — mechanics or process
- **Real examples** — tools, products, case studies
- **Watch-outs** — caveats, limitations, common mistakes

---

## Step 4 — Write the Report

### Template

```
# [Report Title]

**Topic:** [as given]  
**Date:** [YYYY-MM-DD]  
**Prepared for:** [audience from Step 1]

---

## Summary
[3–5 standalone bullet takeaways. Reader should get the full picture from this section alone.]

## Key Findings
[5–7 bullets. Format: **Bold claim or fact** — one sentence of context or implication.]

## Practical Takeaways
[4–6 action bullets. Start each with a verb: Try, Use, Avoid, Check, Set up, etc.]

## What to Watch Out For
[2–4 bullets. Be direct: "This doesn't work well if..." or "Avoid X because..."]

## Sources
1. Author Last, First (or Organization). "Title." Publication. Month YYYY. [URL]
[Every claim must be traceable to a source in this list. Use "n.d." if no date available.]
```

### Formatting rules
- Bullets over paragraphs throughout
- Short sentences — cut filler words
- No jargon; if a technical term is necessary, define it in plain language right after
- **Bold** the most important phrase in each bullet

---

## Step 5 — Save Output

1. Name the file: `YYYY-MM-DD-<short-topic-slug>.md`  
   Example: `2026-04-04-ai-writing-tools.md`
2. Save to: `outputs/`
3. Confirm the file path to the user
4. Offer to expand any section if needed

---

## Completion Checklist

- [ ] Clarifying questions were asked and answered before research began
- [ ] At least 5 credible, dated sources consulted
- [ ] Report follows the template structure exactly
- [ ] Bullets used throughout — no prose paragraphs in findings sections
- [ ] Every key claim backed by a listed source
- [ ] File saved to `outputs/` with correct naming format
- [ ] File path confirmed to user
